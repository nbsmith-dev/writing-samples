Vehicle Management Service · Developer Guide

Query, task, and audit the TC-77 Skylark from the ground.

The VMS API is a RESTful interface for reading vehicle status and issuing non-flight-critical tasking to the TC-77 Skylark Autonomous Air Vehicle. Every request transits the Secure Network Systems (SNS) gateway — authenticated, scoped, and logged.

  GET /vehicles/TC77-0041/status

Ground software never talks to the flight computer directly. It hands a request to the VMS API, which validates it, logs it, and forwards it over the vehicle datalink. The API exposes three functional areas:

Read-only

Status

Vehicle health, position, and fuel state — what the vehicle is doing right now.

Write · 2-person auth

Tasking

Mission plan uploads and loiter/route amendments — what you want the vehicle to do next.

Bulk read

Telemetry export

Recorded flight data retrieval — what the vehicle did on prior sorties.

Security model

Secure Network Systems (SNS)

SNS is the accredited transport layer between ground clients and the VMS API. No client reaches the API except through the SNS gateway, which enforces three controls:

Mutual TLS (mTLS)

Both the client and the gateway present X.509 certificates issued by the SNS Certificate Authority — each side proves who it is before any data moves.

Token-based authorization

After the mTLS handshake, the client exchanges its certificate identity for a short-lived bearer token scoped to specific operations — a time-limited hall pass listing the rooms you may enter.

Session audit

Every request is logged with the client certificate common name (CN), source enclave, and operation performed.

The gateway terminates TLS 1.3 only. Clients presenting expired certificates, revoked certificates, or legacy cipher suites are dropped at the handshake and never reach the API.
Conventions

Base URL & versioning

All endpoints are versioned under the SNS gateway hostname for your operating enclave:

BASE URL
https://sns-gw.enclave.example.mil/vms/api/v2

Breaking changes increment the major version segment (/v2 → /v3). Additive changes — new optional fields, new endpoints — do not.

Task · ~5 minutes

Quickstart: first status query over SNS

Verify your SNS client certificate, obtain a scoped bearer token, and issue your first read-only status query from a Linux workstation.

Before you begin, confirm that your workstation is on an SNS-accredited enclave with routing to sns-gw.enclave.example.mil; that your client certificate (client.crt), private key (client.key), and the SNS CA bundle (sns-ca.pem) are installed under ~/.sns/ with permissions 600; and that curl 8.x, openssl 3.x, and jq are installed.

1

Verify your client certificate

BASH
openssl x509 -in ~/.sns/client.crt -noout -subject -enddate
OUTPUT
subject=CN=gcs-op23.enclave.example.mil, OU=GCS, O=SNS
notAfter=Dec 31 23:59:59 2026 GMT

If notAfter is within 30 days, request renewal from the SNS registration authority before proceeding.

2

Confirm the mTLS handshake

BASH
openssl s_client -connect sns-gw.enclave.example.mil:443 \
  -cert ~/.sns/client.crt -key ~/.sns/client.key \
  -CAfile ~/.sns/sns-ca.pem -tls1_3 -brief < /dev/null

A successful handshake reports Protocol version: TLSv1.3 and Verification: OK. Any other result indicates a certificate or enclave routing problem — stop and contact the SNS help desk.

3

Request a scoped bearer token

BASH
curl --cert ~/.sns/client.crt --key ~/.sns/client.key \
  --cacert ~/.sns/sns-ca.pem \
  -X POST https://sns-gw.enclave.example.mil/vms/api/v2/auth/token \
  -H "Content-Type: application/json" \
  -d '{"scope": "status:read"}' | jq -r '.access_token' > ~/.sns/token
Tokens expire after 15 minutes. Do not cache tokens across sessions.
4

Query vehicle status

BASH
curl --cert ~/.sns/client.crt --key ~/.sns/client.key \
  --cacert ~/.sns/sns-ca.pem \
  -H "Authorization: Bearer $(cat ~/.sns/token)" \
  https://sns-gw.enclave.example.mil/vms/api/v2/vehicles/TC77-0041/status | jq

The response is the JSON status document shown in the overview — mode, position, fuel state, and link state, stamped with the vehicle clock.

5

Revoke the token and clear it from disk

BASH
curl --cert ~/.sns/client.crt --key ~/.sns/client.key \
  --cacert ~/.sns/sns-ca.pem \
  -X DELETE https://sns-gw.enclave.example.mil/vms/api/v2/auth/token \
  -H "Authorization: Bearer $(cat ~/.sns/token)"
shred -u ~/.sns/token

You now have an authenticated SNS session pattern you can reuse for any read-only VMS operation. Tasking requires a separate token with tasking:write scope and two-person authorization.

Reference

Rate limits

The SNS gateway enforces 60 requests per minute per client certificate CN. Exceeding the limit returns 429 with a Retry-After header. To watch your consumption from the command line:

BASH
curl -s -o /dev/null -D - \
  --cert ~/.sns/client.crt --key ~/.sns/client.key --cacert ~/.sns/sns-ca.pem \
  -H "Authorization: Bearer $(cat ~/.sns/token)" \
  https://sns-gw.enclave.example.mil/vms/api/v2/vehicles | grep -i x-ratelimit
