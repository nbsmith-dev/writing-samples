01 — Overview

About this system security plan

A System Security Plan describes the security requirements in place for an information system, and the controls that meet them.

For contractors handling CUI on behalf of the Department of Defense, an SSP is required under DFARS clause 252.204-7012 and serves as the reference document during a Cybersecurity Maturity Model Certification (CMMC) assessment.

This SSP covers the system boundary, control implementation, and external relationships for a fictional system built to demonstrate SSP authoring conventions:

  • The system boundary and the CUI that flows through it
  • How each applicable NIST SP 800-171 control family is implemented
  • Relationships with external systems and service providers
  • Roles and responsibilities for maintaining the system's security posture

04 — Control families

NIST SP 800-171 control families addressed in this plan

NIST SP 800-171 organizes its 110 security requirements into 14 control families. A complete SSP addresses all 14; this sample focuses on three families most relevant to a network gateway appliance handling CUI in transit and at rest.

How to read a control ID

Each green tag you'll see below — for example AC.L2-3.1.1 — breaks down into three parts:

SegmentExampleMeaning
Family AC NIST SP 800-171 control family abbreviation (here, Access Control)
Level L2 CMMC maturity level this requirement maps to
Requirement no. 3.1.1 The specific requirement's number within NIST SP 800-171

AC

Access Control

Governs who and what can access the system, and under what conditions.

SC

System & Communications Protection

Protects information at the system's external and internal boundaries, including encryption of CUI in transit.

CM

Configuration Management

Establishes and maintains baseline configurations and controls changes to the system.

Every control in an SSP is addressed in one of two ways: fully implemented, or documented in a Plan of Action and Milestones (POA&M) with a remediation timeline. This sample illustrates both.

05 — Task

Configure access control on the VSG-100

Configure role-based access control and session enforcement to satisfy NIST SP 800-171 Access Control requirements.

AC.L2-3.1.1AC.L2-3.1.2AC.L2-3.1.11

Before you begin

  • Administrator-level access to the VSG-100 management console
  • An approved list of authorized users and their assigned roles

Procedure

  1. Select Access Control in the VSG-100 management console.

  2. Create a role for each authorized function (Administrator, Operator, Auditor), and assign only the permissions required for that function.

    Don't assign Administrator privileges to accounts used for routine monitoring or reporting.

  3. Assign each authorized user to the role that matches their approved function on the authorized user list.

  4. Set the Session Timeout value to the organization's approved idle-session limit.

    An idle session that exceeds this value is automatically terminated, satisfying AC.L2-3.1.11.

  5. Select Login Attempt Lockout, and set the maximum number of consecutive failed login attempts allowed before an account is locked.

  6. Save the configuration, and review the resulting role assignments in the Access Summary report.

Result: access to the VSG-100 is restricted to authorized users, each limited to the transactions their assigned role permits, with idle sessions terminated automatically.

06 — Task

Configure boundary protection on the VSG-100

Configure the VSG-100's external boundary and encryption settings to satisfy NIST SP 800-171 System and Communications Protection requirements.

SC.L2-3.13.1SC.L2-3.13.8

Before you begin

  • Administrator-level access to the VSG-100 management console
  • An approved network diagram identifying the CUI enclave boundary

Procedure

  1. Select Boundary Protection in the VSG-100 management console.

  2. Define the CUI enclave boundary by identifying which network interfaces carry CUI traffic, using the approved network diagram as reference.

  3. Turn on the managed interface filter, apply a deny-by-default rule set, and then add explicit allow rules only for approved traffic flows.

  4. Under Transport Encryption, select an approved FIPS-validated cryptographic module for all CUI-carrying interfaces.

    Interfaces without an approved cryptographic module selected will not pass CUI traffic once enforcement is enabled.

  5. Select Enforce Encryption for all interfaces identified as part of the CUI enclave boundary.

  6. Save the configuration, and confirm the Boundary Status report shows all CUI interfaces as filtered and encrypted.

Result: communications at the VSG-100's external boundary are monitored and controlled, and CUI is protected by an approved cryptographic mechanism during transmission.
